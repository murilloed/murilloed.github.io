Resumo do projeto

Objetivo e valor para o negócio

Receber dados de infraestrutura, validar sua qualidade e processá-los sem duplicar registros quando houver reenvios ou reinícios. O objetivo de negócio é criar uma base confiável para análises e futuros modelos de machine learning.

Como funciona, em linguagem simples

O fluxo local recebe registros por uma fila assíncrona com capacidade limitada, valida os campos e persiste dados em SQLite. Registros repetidos são identificados; os inválidos seguem para uma fila de erros persistente. Métricas mostram o que foi aceito, rejeitado ou duplicado.

Entenda os itens técnicos

Asyncio permite coordenar tarefas de entrada e saída. A fila limitada evita acumulação sem controle. Idempotência significa que repetir um processamento não cria efeitos duplicados. A dead-letter queue guarda falhas para análise. MongoDB e Spark têm adapters opcionais; AWS tem um template de referência, sem infraestrutura provisionada.

Resumo sintético

Implementei um pipeline local de dados com foco em qualidade, controle de fluxo e recuperação após falhas. Usei fila assíncrona limitada, deduplicação transacional e armazenamento persistente de erros. Testei a idempotência após reinício. Preparei adapters e um template AWS para evolução, mas não apresento o protótipo local como uma plataforma distribuída já operando em produção.

O que mostrar e como ler os resultados

Mostre os contadores do relatório e o teste de reprocessamento após reinício. Explique por que mensagens duplicadas e dados inválidos precisam de tratamentos distintos. O throughput local não demonstra desempenho de Spark distribuído ou custo de operação na AWS.

O que significam as próximas etapas

A evolução exige validar os adapters com serviços reais, executar Spark distribuído e orquestrar etapas com Step Functions. API autenticada, treinamento em compute dedicado, observabilidade e custos ainda precisam ser implementados e medidos.

Como usar “Reproduza o experimento”

O primeiro comando instala o projeto e suas dependências no ambiente Python. O segundo executa a demonstração e gera os resultados. O terceiro executa os testes automatizados. Para apresentar, mostre o problema, rode a demonstração e interprete os resultados; os testes verificam comportamentos específicos e não comprovam desempenho em produção.

Implementação atual

Fila asyncio limitada, validação, deduplicação transacional em SQLite, dead-letter persistente e métricas; adapters MongoDB e Spark opcionais; template AWS SAM para ingestão S3/SQS/Lambda com DLQ e IAM restrito ao bucket do projeto.

Próximas etapas

Testar adapters com serviços reais; executar Spark distribuído; orquestração Step Functions; treinamento em compute dedicado; API autenticada; monitoramento e custos; não há infraestrutura provisionada.
